## 2026-10-16 - POST-EV2-Z7: product identity acceptance

- **POST-EV2-Z7** made the exported clean canvas carry no source campaign identity. The root `README.md` shipped RHC's README (COPY) declaring itself the live Rolling High Club campaign; it is now GENERATE_EMPTY, a fixed campaign-neutral policy constant that names no campaign and routes only into retained control surfaces. `characters/madma/NARRATIVE_DIRECTION.md` shipped a neutral generated body at a campaign-specific path while the exporter preserved the named `characters/madma/` folder skeleton (and the empty `npc/profiles/bor-family/`); those paths are now EXCLUDE directory prefixes whose stale folder skeletons are omitted via the policy's `identity.omitted_skeleton_prefixes`. A new `identity` policy block declares the source-owned identity the *emitted artifact* must not carry. Identity is checked in two stages: an early expected-tree preflight over the planned output paths and intended bytes, so a predicted leak fails fast before any output tree is created; then an independent post-materialization inspection of the ACTUAL completed output via one strict, no-follow `os.scandir` walk -- every emitted file and preserved directory skeleton, each entry's no-follow filesystem kind read with `os.lstat`, each declared content surface (`README.md`) read through its real on-disk bytes (only from an `lstat`-confirmed regular path, never by following a substituted link out of the canvas), the actual path/kind inventory compared against the authorized expected inventory, every emitted regular file's real bytes (or a legitimate Git `120000` COPY symlink's real `readlink` target) attested against the exact intended digest, and every emitted regular file's real POSIX mode verified against its authorized Git `100755`/`100644` mode. The walk fails closed on any unscannable directory or unreadable entry, so `os.walk`'s documented silent drop of a `scandir` error (or a swallowed `DirEntry` classification error) can never certify a partial inventory. A leaked path token, a mutated README, an extra (even token-free) or missing materialized path, a substituted path kind (a regular file replaced by a symlink), altered bytes, a changed executable bit, or any unreadable path/scan failure fails the export closed before any accepted receipt is written; the kind contract keeps a legitimate source-authorized Git `120000` symlink as an actual symlink rather than silently treating it as a regular file; POSIX permission fidelity is asserted only where the host exposes permission bits (`os.name == 'posix'`), where the Ubuntu CI job proves it; on acceptance the receipt records a top-level machine-readable `artifact_attestation` whose `posix_mode` is `verified` only where those bits are observable and the mode contract fully passed, otherwise `not_observable` -- never a silent `verified` -- alongside the identity-only machine-readable `identity_acceptance` evidence for the completed tree. The check is narrowly scoped (no generic `RHC` substring removal; stable runtime/API identifiers, reusable docs and provenance stay out of scope). RHC's own README, canon and gameplay are unchanged; exporter classification elsewhere, COPY bytes/modes, reference integrity, `ENGINE_VERSION 1.1.0` and the exported product's CI are unchanged. Merge identity recorded at closeout.

route deduplication is by normalized route and dynamic/static classification, so the same route occurring both statically and dynamically keeps both classifications (a missing static dependency still fails the export closed and the dynamic fragment is still recorded as unproven); a static `working-directory` must be a real exported DIRECTORY -- satisfied by an exported file at or under it, never by an exported file at the exact path itself (a runner cannot change directory into a file) and never by an empty preserved skeleton or all-EXCLUDE directory;
